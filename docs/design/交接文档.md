## 4. 构建、运行、测试、打包

### 4.1 Windows（MSYS2 UCRT64，完整功能目标环境）

环境：Windows 10/11 + MSYS2 UCRT64（Qt 6.11.x、GCC 16.x、CMake、Ninja、FFmpeg 9.x 开发包）。

```powershell

$env:Path = 'C:\msys64\ucrt64\bin;' + $env:Path

# 1) 构建
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=C:/msys64/ucrt64 -DCMAKE_BUILD_TYPE=Release
cmake --build build -j8

# 2) 单元/集成测试（引擎用例需 Vulkan GPU 与 bin/realesrgan 完整）
ctest --test-dir build --output-on-failure

# 3) 四条链路人工验收（真实素材，输出到 build/verify）
build\tests\resr_pipeline_verify.exe --out build\verify

# 4) 运行（本机需要管理员权限；普通用户启动可能无法打开窗口）
build\real-esrguisoft.exe
#    自动化截图请用提权脚本：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\capture_admin.ps1 `
    -Exe build\real-esrguisoft.exe -OutDir "$env:TEMP\resr-shots" -Name light -Theme light

# 5) 打包（唯一入口：工作区同级的 cxx_pkg 0.3+，Windows/MSYS2 能力）

#    → dist/real-esrguisoft-<version>-win64.zip（自包含：Qt 插件/第三方 DLL 闭包/
#      bin/realesrgan 引擎+模型/README/LICENSE + SHA256SUMS，仓库外解压可运行）
#    项目内不再维护自写打包脚本（原 tools/deploy.ps1 已删除）
```

## 5. 三方库内嵌说明

### 5.1 stacklog（日志）

- 位置 `third_party/stacklog/`，MIT，纯 C++11、无 Qt 依赖。
- **接入方式**：`src/common/logger.h/.cpp` 是**兼容层**——保留原有 `LOG_DEBUG/INFO/WARNING/ERROR` 宏与 `Logger::instance()` 接口，内部转 stacklog 落盘，调用点零改动。
- 行为：日志目录 `<程序目录>/logs/`（设置页展示并可打开），文件 `real-esrguisoft.log`，5 MB 轮转保留 `.1`–`.5`；每行含调用点 `文件:行号`；保留控制台 tee；退出前 `Logger::instance()->shutdown()`。
- Windows 中文路径由 `std::filesystem` 补丁处理；日志/构建路径已随真机验收覆盖，
  引擎输入/输出中文路径的中转与交互行为列入 task-29 待验证。

### 5.2 singleproc（单实例）

- 位置 `third_party/singleproc/`；上游仓库同步改造。
- **Windows 后端**（原库纯 POSIX）：
  - 锁：`CreateFileW(share=0)` 独占句柄，`ERROR_SHARING_VIOLATION` → `AlreadyRunning`；进程退出/被强杀由内核释放。
  - 门铃：命名管道 `\\.\pipe\singleproc-<user>-<key>` + 重叠 IO；`doorbell_fd()` 在 Windows 恒为 `-1`，改用 `doorbell_wait_handle()` 或定时 `process_doorbell(0)`。
  - 路径按 UTF-8 解释，支持中文目录。
- 集成：`main.cpp` 在 `QApplication` 之后做判定；二次启动通过门铃唤醒主窗口，主实例用 200ms `QTimer` 轮询门铃。
- 验证：Linux 上上游 `ctest` 4/4 通过；集成后二次启动日志 `Another instance is already running, notified it and exiting`，退出码 0。Windows 后端已随 task-23 做双会话/二次启动真机验证（见 `windows-verification.md`）。

### 5.3 FFmpeg（媒体）

- 位置 `third_party/ffmpeg/ffmpeg-9.0.2/`（源码，不含 `.git`），另有 `build-ffmpeg.ps1` / `build-ffmpeg.sh`。
- 查找优先级：系统 `pkg-config` → `-DFFMPEG_ROOT=<prefix>` → `third_party` 源码构建产物；实现见 `cmake/FindFFmpeg.cmake`。
- 运行时链接 `avformat/avcodec/avutil/swscale/swresample`，**不再有 ffmpeg.exe / ffprobe.exe**；视频探测、拆帧、编码、音频流拷贝都在进程内完成。
- 许可证 LGPL：分发时注意动态链接、随附源码与许可证（详见 `docs/design/ffmpeg-integration.md`）。

- 规范：`docs/design/ccswitch-v4-ui-spec.md`（含数值来源行号）。

- 壳层：无边框窗口 + 自绘窗口按钮 + 左侧栏 + 顶栏 + `QStackedWidget` 页面（工作台/设置/关于）；快捷键 `Ctrl+O`、`Ctrl+Shift+O`、`Ctrl+Shift+S`、`F5`、`Ctrl+B`、`Ctrl+Shift+T`、`Ctrl+1..4`、`Esc`；任务控制 `Ctrl+Enter`（开始/暂停/继续）、`Ctrl+Shift+X`（停止）。

- **设置页**（5 张卡）：外观（浅/深/跟随系统）、超分引擎路径（选择文件/目录/恢复自动发现 + 来源提示）、日志（目录展示 + 打开）、处理默认值（恢复出厂）、运行环境（Qt 版本/引擎/单任务串行说明/图标许可）。
- **关于页**：应用图标、版本号（CMake `project(VERSION)` 经 `RESR_APP_VERSION` 注入）、简介、技术标签、开源许可对话框、致谢。

### 6.1 参数语义澄清（视频模式 / 旧版差异）

- GUI 的**视频模式复用「基本设置」卡**，但不显示「图片类型」行：模型下拉直接提供
  `realesr-animevideov3`（默认推荐，4x）以及 `realesrgan-x4plus` /
  `realesrgan-x4plus-anime`，并显示「视频推荐模型」提示。
- 图片/视频两种模式的基本设置分别保存，切换模式不会用视频默认值覆盖图片选择；
  动漫视频模型放大倍数可选 2x/3x/4x，**默认 4x**（旧 CLI 的 2x 默认不是 GUI 行为）。
- 视频输出容器为 原格式/mp4/mkv/avi/mov/webm（**下拉已不含 gif**）；GIF 输入（动态）
  会拆帧后自动按 MP4 输出。旧版打包工具的 GIF 输出未移植，如需可后续补 GIF 编码。
- 视频「刷新」语义已拆分：页头刷新 = 重置会话；视频设置卡内刷新 = 恢复视频默认值。
- 高级参数「线程数」不是摆设：合法 `load:proc:save`（默认安全值 `1:1:2`）会作为 `-j` 传给引擎；非法/空值回退 `1:1:2`。

### 8.2 已知限制（不必立刻修，但要知道）

- **Linux 超分引擎不可用**：`bin/realesrgan/realesrgan-ncnn-vulkan.exe` 是 Windows PE；
  Linux 可构建/运行 GUI 与媒体层，依赖引擎的 4 条链路用例 QSKIP。如确需 Linux 超分，
  需自备 Linux 版引擎并在设置页指定（当前未适配/未验证）。
- **视频输出不含 GIF**：输出容器为 mp4/mkv/avi/mov/webm；GIF 输入自动按 MP4 输出。
  旧版打包工具的 GIF 输出能力未移植，如需可后续补 GIF 编码。
- **失败/取消可能留下半成品文件**：引擎/编码失败或取消时已写出的产物留在最终路径
  （覆盖模式会先截断旧成品）；后续可改 `.part` + 原子 rename。
- **Windows 仓库目录的受限令牌（环境策略）**：本机对从仓库目录内启动的 exe 施加受限
  令牌（只能写仓库内路径），会导致引擎“中文/外部路径”失败；复制到仓库外或使用 dist 即
  正常。非产品缺陷；验收请在仓库外副本/dist 中运行，或核实该策略。
- **视频拆帧占磁盘**：1080p 长视频拆帧可占数 GB 临时空间（与旧 Python 方案同量级）；
  无断点续传，中断后临时目录由任务清理逻辑回收。
- **超分引擎仍是外部 exe**：`bin/realesrgan/realesrgan-ncnn-vulkan.exe`（官方 v0.2.0，已是最新）。
  其**退出码不可信**（失败也返回 0），成功判定依赖产物存在 + stderr 关键字；进度输出全在 stderr，
  格式如 `16.67%`。
- **动态链接 FFmpeg**：开发构建依赖 MSYS2 的 FFmpeg DLL；分发请用工作区同级的
  `cxx_pkg`（`cxx_pkg.ini`，PE 导入闭包自动补齐第三方 DLL 并打 zip），或按
  `third_party/ffmpeg/build-ffmpeg.*` 构建静态库后全静态链接。
- **Windows 缺 valgrind**：内存检查建议在 WSL2/Linux 跑，或改用 ASan（需装 `compiler-rt`）；
  本仓库 `audit.toml` 默认只启用 compat，tidy/cpd/asan/valgrind 在 Windows 显式关闭，
  Linux/WSL 可按 `docs/ci.md` §6 显式补跑。
- **本机需管理员启动**：本机 Windows 环境以普通权限启动无法打开窗口，自动化验收请用
  `tools/capture_admin.ps1`（提权内部完成启动/截图/结束，避免调用方卡死）。
- **单实例与并行截图冲突**：同一 `XDG_RUNTIME_DIR` 下不能并发跑多个实例（第二实例
  静默退出 0 且不产截图）；并行验收需各自独立 runtime 目录。
- **Windows 非引擎交互回归已完成（task-29 A 组）**：真实鼠标键盘/UIA 交互 16/16 PASS、
  离屏视觉 16/16 PASS（PASS 45/59、0 产品缺陷）；剩余 **DPI 100/125%、系统语言切换、
  原生对话框深度操作、播放器/拖放、超长路径** 等为 MANUAL/DEFERRED，见 §7.7。
- **Windows/Linux clang-format 版本差**：Windows 23.1.5 与 Linux 21.1.8 对少量基线文件
  的换行/对齐决策不同，`standardize --check` 在 Windows 会报 4 个未改文件差异；建议 CI
  固定 clang-format 版本（或统一 21.x）。修复文件本身无差异。
- **中英双语的已知限制**：Qt 内建对话框按钮（QFileDialog/QMessageBox 标准按钮）
  跟随 Qt/系统语言，不随应用语言（未内置 qtbase 翻译）；处理中任务已显示的
  「最后一条服务详细消息」保持旧语言直到下一次状态更新。
- **TDR/GPU 环境（本机实测，2026-11-15）**：该 Windows 真机存在 NVIDIA 驱动不稳定
  历史；引擎高负载会触发/放大 `nvlddmkm 153`/`LKD_0x141_Tdr`，`TdrDelay=10s` +
  独显直连会放大为黑屏。已做 TDR 加固（安全参数/串行冷却/降级重试/孤儿进程清理），
  但**不宣称根治**；独立复核确认 GamePP SDK 注入（GPP64.dll）曾致应用 18 次崩溃、
  VMware mksSandbox/GameViewer/NVIDIA OTA 同窗口活动。GPU 真机四链路/交互验收
  需在环境隔离（A/B/C/D 实验）后进行，当前按用户决定暂缓。
- **Windows 全控件/全功能深度测试（task-29）部分完成**：非引擎 A 组已完成
  （PASS 45/59、0 产品缺陷，见 §7.7）；**engine-gated 36 条**（真实引擎四链路/编码矩阵/
  暂停停止/性能/失败重试）与 **MANUAL 项**（DPI/系统语言/原生对话框深度等）等环境隔离
  A/B/C/D 放行；**A-8 视频帧分批的真实视频复验**同样 PENDING（用户要求不再做引擎实验）。
- **已知 minor 清理项**：clang-tidy 约 41 条 warning（多在性能/窄化类）；CPD
